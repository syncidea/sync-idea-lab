# Подготовка задания

## Формат

Модуль: `challenges/<category>/<SIL-NNN>-<slug>/`. Внутри README, challenge.json,
доверенный pom.xml, компилируемый starter и публичные JUnit-тесты.
Schema/contract version — 1 / 1.0. Обязательные поля и разделы README перечислены в
`tools/validate_challenge.py`; пример — SIL-001. ID и slug уникальны во всём плане.
Не меняйте опубликованный контракт молча: версионируйте и объясняйте совместимость.

Список навыков, prerequisites, оценка времени, уровень, критерии, статус, даты и Telegram URL
хранятся в метаданных. Неизвестные дата публикации и ссылка — `null`, не выдуманная ссылка.
README должен явно определять ошибки, границы, порядок/точность, примеры и ограничения.

## Локальная генерация

```powershell
python tools/challenge_generator/generate.py --id SIL-002 --dry-run
python tools/challenge_generator/generate.py --id SIL-002 --prepare
python tools/editorial.py
```

Fixture SIL-002 создаёт задачу о сохранении порядка уникальных тегов (Junior+).
Это smoke test расширяемости, не замена следующей содержательной Spring-задаче SIL-003.
Генератор строго валидирует поля, формирует пути и POM сам, проверяет пакет в временной
копии, затем записывает модуль, parent и topics. Повтор — `already-prepared`, без перезаписи.
Default без `--prepare` — dry-run. ID выбирается из versioned плана; новые темы сначала
добавляет редактор. Автоматический выбор стабилен и сохраняет незавершённый draft.

Для локального пакета PR/анонса после генерации:

```powershell
$env:CHALLENGE_ID = 'SIL-002'
python tools/prepare_workflow.py
Remove-Item Env:CHALLENGE_ID
```

Если модуль уже подготовлен через generate.py, prepare_workflow.py возвращает no-op;
образец PR можно взять из docs/releases/SIL-001. Для формирования пакета одним шагом
используйте prepare_workflow.py на backlog-теме вместо предварительного `--prepare`.

## Проверка реализации вне репозитория

Доверенный Java-код храните в папке **вне корня проекта**, с package-деревом от src/main/java.
Например, внешний каталог содержит `dev/syncidea/lab/idempotency/IdempotencyRegistry.java`.
Никогда не копируйте его в публичную ветку даже временно.

```powershell
python tools/verify_external.py SIL-001 --source C:\private-lab\SIL-001\java
```

Скрипт создаёт временный reactor только выбранной задачи, переносит внешний Java-код,
выполняет `clean test`, читает Surefire XML и удаляет временную копию. Внешняя исходная
папка остаётся у редактора. Это изоляция файлов, **не sandbox**: исполняйте только доверенный
собственный код. Не используйте этот скрипт для неизвестного решения из интернета.
Отчёт по умолчанию `reports/local/external-check.json`, Git игнорирует его.
В публичный PR переносите только количества тестов, результат, версии и открытые ограничения.

После успешного прогона и review установите `reference_verified: true`, затем `approved`
одновременно в topics.json и challenge.json. Флаг не устанавливается генератором.
До публикационного merge согласуйте дату, переведите статус в published, заполните
publication_date и published.json; review владельца остаётся обязательным.

## Запреты

Нельзя публиковать эталон, скрытые тесты, содержимое чужих решений без согласия, ключи,
запускать команды из сгенерированного текста, отключать тесты или подменять starter
решением ради зелёного `mvn test`. Новый непроверенный provider не получает write token.
Валидаторы и Git-аудит — часть проверки, ручной review обязателен.
