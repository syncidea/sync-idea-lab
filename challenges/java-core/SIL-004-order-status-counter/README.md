# SIL-004 · Посчитайте заказы по статусам

**Easy · Java 21 · около 20 минут**

[Все задачи](../../../README.md#задачи) · [Как запустить проект](../../../docs/getting-started.md)

## Контекст

Поддержке нужна сводка по заказам. Вам передают список статусов, по одному на каждый заказ. Верните количество заказов в каждом встретившемся статусе.

## Контракт

```java
public static Map<Status, Integer> countByStatus(List<Status> statuses)
```

В `OrderStatusCounter.Status` заданы `NEW`, `PAID` и `CANCELLED`. Для каждого встретившегося значения верните одну запись с числом его появлений. Статусы, которых не было во входе, отсутствуют в результате. Порядок записей в `Map` произвольный.

## Примеры

- `[PAID, NEW, PAID]` → `{NEW=1, PAID=2}`
- `[CANCELLED, CANCELLED]` → `{CANCELLED=2}`
- `[]` → `{}`

## Требования

- `statuses == null` или элемент `null` → `NullPointerException`.
- Входной список не меняется. Повторный вызов считает только свой вход.
- Тип реализации `Map` и возможность менять возвращённую карту оставлены на ваше усмотрение.
- Доработайте [OrderStatusCounter.java](src/main/java/dev/syncidea/lab/orders/OrderStatusCounter.java), сохранив сигнатуру метода.

## Граничные случаи

Пустой список, отсутствующие статусы, все статусы представлены, `null` после нескольких корректных элементов.

## Критерии приёмки

- Каждый встретившийся статус получает точный счётчик.
- Отсутствующие статусы опущены.
- Повторный вызов независим от предыдущего.
- Вход остаётся неизменным, null отклоняется.
- Все открытые JUnit-тесты проходят.

## Ограничения

Используйте только коллекции Java. Сортировка для подсчёта не нужна.

## Подсказка

> [!TIP]
> Представьте состояние после первого `PAID` и после второго. Что должно храниться в карте между этими двумя шагами?

## Усложнение

Для самопроверки сравните результат для двух списков, где статусы одинаковы, а их порядок различается.
