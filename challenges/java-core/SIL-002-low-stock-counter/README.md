# SIL-002 · Какие товары нужно пополнить

**Easy · Java 21 · около 15 минут**

[Все задачи](../../../README.md#задачи) · [Как запустить проект](../../../docs/getting-started.md)

## Контекст

У каждого товара на складе есть остаток. Помогите сотруднику узнать, сколько товаров пора пополнить. Товар попадает в список, если его остаток равен порогу или меньше него.

## Контракт

```java
public static int countLowStock(int[] quantities, int threshold)
```

Каждый элемент массива — остаток одного товара. Верните число элементов со значением от `0` до `threshold` включительно. Одинаковые остатки у разных товаров считаются по отдельности.

## Примеры

- `[7, 2, 0, 3]`, порог `2` → `2`
- `[4, 4, 5]`, порог `4` → `2`
- `[]`, порог `3` → `0`

## Требования

- `quantities == null` → `NullPointerException`.
- Отрицательный порог или отрицательный остаток → `IllegalArgumentException`.
- Порог `0` допустим. Массив после вызова должен сохранить своё содержимое и порядок.
- Доработайте [StockCounter.java](src/main/java/dev/syncidea/lab/stock/StockCounter.java), сохранив сигнатуру метода.

## Граничные случаи

Пустой массив, нулевой порог, остаток ровно на пороге, отрицательный остаток в конце массива.

## Критерии приёмки

- Остаток, равный порогу, учитывается.
- Нулевой порог учитывает только нулевые остатки.
- Некорректные данные вызывают оговорённые исключения.
- Порядок и значения массива сохраняются.
- Все открытые JUnit-тесты проходят.

## Ограничения

Используйте стандартную библиотеку Java. Достаточно одного прохода по массиву.

## Подсказка

> [!TIP]
> Выберите три значения для проверки границы: ниже порога, ровно на пороге и выше него. Правило включения должно дать разные результаты для двух последних.

## Усложнение

Для самопроверки посчитайте результат для массива, в котором все товары лежат ровно на пороге.

## Запуск

Запустите команды из корня репозитория в PowerShell.

```powershell
.\mvnw.cmd -pl challenges/java-core/SIL-002-low-stock-counter clean test-compile
.\mvnw.cmd -pl challenges/java-core/SIL-002-low-stock-counter clean test
```

Первая команда проверяет, что код и тесты компилируются. Вторая запускает тесты.
До реализации ожидается `UnsupportedOperationException`. В Linux и macOS используйте `./mvnw`.
