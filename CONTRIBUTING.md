# Как участвовать

Основные задания бесплатны. Обсуждение и документация на русском; код и Java API на английском.
Код проекта доступен по MIT, тексты заданий — по CC BY 4.0. Подробности в [правилах лицензирования](LICENSE-SCOPE.md).

## Учебная сдача: submission

1. Выберите ID и прочитайте README задачи, контракт и тесты.
2. Создайте fork и ветку для вашей задачи, например `submission/SIL-002`.
3. Изменяйте только `challenges/<category>/<id-slug>/src/main/java/**/*.java` одной задачи.
   Можно добавлять Java-классы. Сохраните API. Нельзя изменять тесты, README заданий,
   метаданные, POM, `.mvn`, workflows и проверяющие скрипты. Symlinks и исполняемые файлы запрещены.
4. Запустите `./mvnw -pl <module> clean test` (Windows: `.\mvnw.cmd`).
5. Откройте PR с заголовком **`[submission SIL-002] Краткое название`**, подставив ID вашей задачи.
   CI сверяет ID в заголовке с путями изменённых файлов.
6. Заполните шаблон: подход, сложность, тесты, оставшиеся вопросы. Не прикладывайте секреты.
7. Получите CI/review, внесите исправления. После разбора PR **закрывается без merge**.

Решение участника не должно попадать в starter на `main`. Поэтому `publication-policy`
в учебном PR **намеренно красный**, `editorial` пропускается. Результат решения —
отдельный job `submission`; он должен быть зелёным. Красный запрет merge не означает,
что решение неверно. Не просите сопровождающего обходить этот запрет.

PR публичен: другие участники могут прочитать решение. Гарантированного срока review
и автоматического доказательства правильности нет. Тесты открыты, скрытых проверок нет.
Лучшее решение можно разобрать в посте только с отдельного согласия автора и указанием авторства.

## Сообщить об ошибке

Если нашли ошибку в условии, тестах или сборке, откройте
[отдельный issue](https://github.com/syncidea/sync-idea-lab/issues/new/choose).
Укажите ID задачи, команду, ожидаемый и фактический результат.
Предлагаемые случаи для тестов можно описать в issue или в тексте учебного PR.
Для отдельного PR с исправлением общей документации используйте заголовок `[documentation] ...`.

Review учитывает контракт, аргументацию, тесты, понятность и сложность решения. Общаемся
уважительно, см. [CODE_OF_CONDUCT](CODE_OF_CONDUCT.md). Зелёный CI — полезная проверка,
но не гарантия отсутствия гонок, плагиата или злонамеренного кода.
